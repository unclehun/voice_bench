## 数据准备

准备至少 10 条录音，录音 9、10 均有长于一屏的识别文字和 DeepSeek 纠错结果，包含多条待确认与已自动采用建议。检查两种识别引擎各自的框块，以及首页和详情中的历史运行记录。记录操作前的录音名、引擎、可见建议。

## 检查矩阵

| 操作 | 预期行为 |
|---|---|
| 录音 10 中接受一处建议，等待保存结束；重复多次 | 始终位于该录音；列表顺序、其他录音的展开状态不变；底部状态出现／消失不插入内容行 |
| 保留原文、撤销已采用修改，再次接受 | 只更新该条建议，操作按钮仍占原来位置；纠错段落只标记当前已采用修改 |
| 对两个识别引擎的 DeepSeek 结果分别执行上述操作 | 只更改目标引擎的纠错结果；其它结果不受影响 |
| 展开／收起原始文字、纠错全文、修改建议、历史片段说明、纠错结果 | 只变更对应区域；不触发识别、重新纠错、播放或导航；视口不会因卡片高度估算跳到相邻录音 |
| 收起详情页中的修改建议，滚出屏幕后返回 | 保留用户选择，不因再次出现而自动展开 |
| 识别、首次纠错、菜单重新纠错、停止 | 状态提示固定在底部；运行只针对目标录音／结果；结束时不改变录音顺序或滚动到其它录音 |
| 播放／停止、打开详情、返回首页 | 只触发对应操作；返回后检查原位置及展开状态 |
| 详情中计算 CER、导出结果，关闭分享页 | 状态提示不在顶部插入行；导出和 CER 使用修正后的纯文字，段落中的旧词不会重复计入 |
| 删除弹窗取消／确认 | 取消不改变列表；确认只移除目标录音（移除后的内容自然补位），不影响其它录音结果 |
| 设置中导入模型、准备 Apple 资源、检查状态、保存／删除 Key | 仅对应按钮生效；任务状态不在 Form 顶部插入 Section；错误提示关闭后仍在当前页 |

## 段落显示与保存

1. 接受“王小明 → 王晓明”：上下文保留，整个“王小明”为红色删除线，绿色“王晓明”紧接其后，不将共有的字拆到其它位置。
2. 同一段有两处修改时，分别接受／撤销，确认各自原始位置准确；包含 emoji、换行、重复词及不同长度的修正文也应准确。
3. 待确认、已保留原文、未采用的建议不进入段落标记；自动采用的修改与人工接受的修改使用相同标记。
4. 展开全文后接受一处修改，确认全文仍展开；收起状态也应保留。
5. 重启 App 后，已采用决定、原文、绿色修正文均保持一致；旧版结果仍可阅读。
6. 在列表顶部、中部、底部以及较大系统字体下执行关键操作；在已有多条长录音时留意首屏加载和滚动流畅度。

1. 以含旧本地纠错与 DeepSeek 数据的录音升级，启动后检查所有历史运行的旧 `correction` 键已删除；DeepSeek 文本、建议 ID、已接受／保留决定不变。

## 0.12.1 请求日志检查

1. 展开对应识别框块的“DeepSeek 请求日志”，点击一条后应在独立页面展示完整响应和 arguments，可复制及分享；关闭后滚动位置保持。
2. 模拟第一次缺少 edits、重试成功，再手动纠错：前两次尝试保留同一个操作 ID，手动请求使用新操作 ID；重启后前次原始错误、HTTP 状态、响应 ID 仍可查看。
3. 验证真实捕获的单层 function_calls 包装兼容解包后仍显示原始响应，并标注兼容处理；缺少真实字段或含混结构不得默认成空修改。
4. 密钥不能出现在请求日志、原始响应回显、分享正文或报告中；仅允许 Content-Type 等诊断响应头，禁止 Authorization／Cookie。
5. 连续请求超过 20 次只保留最近 20 次；删除录音或清除所有数据后日志随运行数据删除。
